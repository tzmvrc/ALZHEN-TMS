# Trip Details simplification and downloads — October 30, 2026

## Outcome and root causes

- Removed Manage assignments & cargo, its page state/handlers, orphan modal component and dedicated obsolete browser test. Shared assignment, crew, cargo APIs and their other management interfaces remain intact.
- Removed Trip Data & Photo Tools, including its gallery, product-photo controls, product detail dialog, unused imports/state and exclusive styles. Photos & Records opens directly as the document gallery.
- Manage Reports already passed an immutable internal `trip_id` to the canonical Master List query. This was retained, not replaced with dispatch/DR/plate filtering. Added a defensive trip-ID check in the rendered projection, a trip-specific empty state, clearer title/context, and adversarial scope tests. No second spreadsheet or independent data source was created.
- The image query selected assignment, stop and event metadata, but `withSignedUrl` discarded those fields. The response now preserves them for accurate grouping. Existing downloads also used the original uploaded filename and had no archive service.
- A legacy header-button rule forced the new export action into a 44px square. Fixed its specificity and added responsive label-containment assertions.

## Gallery and download behavior

The gallery retains search, assignment/stop/type/status filtering, original previews, download actions, rejected PODs and replacement history. It groups records using persisted stop and assignment IDs. Header actions remain visible while the body scrolls.

Individual image downloads use the authenticated backend. Filenames are generated from persisted image DR and stop/store relationships, with the stop DR as a fallback; OCR text is never used for naming. Invalid filename characters and reserved names are sanitized, actual image extensions are preserved/corrected from stored MIME metadata, and shared DR/destination names receive stable sequence suffixes. Records without reliable associations use their persisted filename and record ID. Download controls have icons, hover underlines, touch targets and keyboard focus states. Non-image PDF documents retain their existing authorized original download.

Export All Images always requests the current trip's complete submitted image collection, independent of gallery filters. Metadata is read in pages and scoped by `trip_id` at every query. Original receipt images of every review status and other submitted operational photos are included; uncommitted upload drafts and non-image documents are excluded. Legacy event-to-stop relationships are resolved within the same trip.

The server fetches original files through authorized, short-lived Storage access and builds a ZIP on temporary disk, processing one file at a time. The browser does not buffer the archive in JavaScript memory. Stop/DR folders and collision-free filenames are generated by the same naming helper used for individual downloads. A failed image causes the job to fail with file details; an incomplete ZIP is never made downloadable.

Export status and ticket endpoints use the existing authentication/session and ADMIN/STAFF middleware. Jobs belong to the initiating profile and trip. A ready archive is downloaded using a random, one-use, sixty-second capability, issued only after normal session authorization; this grants access to one prepared ZIP, not Storage. Responses are non-cacheable, service-role credentials remain server-only, and Storage URLs/paths are not included in job responses. Existing audit middleware records authenticated export requests.

## Bounds and limitations

- Up to 5,000 metadata records, 512 MiB of image bytes, 25 MiB per image and ten minutes per export.
- Two simultaneous preparations and eight retained jobs per backend process. Ready ZIPs expire after fifteen minutes. Cancelled/failed work is cleaned up; original Storage objects are never changed.
- Jobs are process-local. A backend restart requires starting the export again; a multi-instance installation needs sticky routing for these temporary jobs.
- Live operational files were not exported, and production-scale throughput was not benchmarked. Gallery rendering is progressive; gallery metadata still uses the existing trip-scoped collection endpoints.
- PDFs remain accessible as documents but are not part of Export All Images.
