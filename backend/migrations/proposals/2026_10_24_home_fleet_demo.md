## Cleanup - prepared, not executed

Review [2026_10_24_home_fleet_demo_cleanup.sql](2026_10_24_home_fleet_demo_cleanup.sql) before retiring the demonstration. It:

1. Validates the exact trip IDs, dispatch labels, ownership tags and existing Admin role.
2. Rejects shared master-data references, including references with ON DELETE SET NULL and legacy driver updates without a driver FK.
3. Runs the existing whole-trip impact check and refuses additional operational records, attachments or financial dependencies.
4. Deletes the five isolated trip graphs through the existing whole-trip deletion function, including caches, then deletes only their exact owned master IDs with normal FK protections enabled.
5. Retains normal deletion journals / audit history. It never touches earlier `d0241024-...` demo records, profiles, real GPS or operational records.

The read-only deletion impact API reported no blockers for the five exact trips, with 10 stops, 20 lines, 20 allocations, 10 stop links, 25 events, 5 demo driver updates and 5 cached routes, and zero financial, attachment or tracking-location dependencies.

Nothing in this document instructs running cleanup now. It is deliberately conservative: newly added records or shared dependencies require review, not forced deletion. The existing Admin Delete Entire Trip preview/confirmation UI is also available for each dispatch.
